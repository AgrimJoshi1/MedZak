# Medzak Healthcare website: Next.js + TypeScript (v3.0 preview)

The whole Medzak site rebuilt as a typed React app and exported as plain static files.
The original static site in `../medzak-website-v2.1/` is **not touched**; this folder is a separate project
that nothing else depends on. Nothing here has been committed or pushed.

## Run it

```bash
npm install          # once
npm run dev          # http://localhost:3000, hot reload; visits every page once at start-up (see below)
npm run dev:plain    # the same server without that warm-up
npm run build        # type-checks, then writes the finished site to out/
npm run typecheck    # TypeScript only
```

The dev server only builds a page the first time it is asked for, which makes the first click to each page slow.
`npm run dev` visits all pages once as soon as the server is ready (`scripts/dev.mjs`, the log line says
`[warm] … pages compiled`), so moving between pages is instant after that. The built site has no such delay.

`out/` is a normal static site (HTML, CSS, JS, images). Upload its contents to the same hosting as today, or
preview it with any static server, e.g. `python -m http.server 8000` from inside `out/`.
`public/htaccess.example` has Apache settings for it (caching, the 404 page, redirects from the old
`/about-us.html` style addresses); rename it to `.htaccess` after review.

Node 18.17 or newer. No Tailwind, no animation library, no form library: 3 runtime dependencies (`next`,
`react`, `react-dom`), so the first-load JS is about 100 kB.

## What changed from the static site

| | Static site | This app |
|---|---|---|
| Stack | HTML + one CSS file + one JS file | Next.js 14 App Router, React 18, strict TypeScript, static export |
| Content | typed in each page | typed data in `src/data/*` (tiles, team, products, nav, ticker, pages), rendered by components |
| Navigation | generated by a Python script | one `NAV` array drives the header, the mobile drawer and the search palette |
| Images | hand-sized | `scripts/gen-images.mjs` reads every file's real size, so each `<img>` has `width`/`height` and a `srcset` (no layout jump) |
| Font | Inter + Red Hat Display | Atkinson Hyperlegible Next, self-hosted: made for legibility, which suits a clinical audience |
| Colour | navy + blue + teal accent | clinical teal on cool paper white, with deep ink-teal bands; orange is kept for the primary action |

### Colour

A hospital reads as clean, cool and calm, so the palette is built from surgical-drape teal and ink rather
than generic tech blue. Orange (the brand colour) is the action colour: **BOOK A DEMO** and the other primary buttons.

| Token | Light | Dark | Use |
|---|---|---|---|
| paper | `#f6faf9` | `#061a21` | page |
| ink | `#0b2530` | `#e8f4f5` | text (15:1 on paper) |
| teal | `#087578` | `#4fd0c8` | links, markers, measured values (5.2:1 on paper, 4.6:1 on the teal wash) |
| deep | `#062c37` | `#04141a` | facts band, call to action, utility bar |
| orange | `#f47b30` | same | BOOK A DEMO, with navy text (5.8:1) |
| imaging strip | `#d9486a #e9a53b #5a80a8 #3fbf86` | same | the four MeiboX imaging types, in one place only |

Light and dark themes both follow the system setting and the header toggle remembers the choice.

### Layout and interface ideas

The look is a **diagnostic suite**: light pages carry the content, and dark "scan bay" sections (the Home hero,
every page header, the instrument panel, the call to action) are the lit instruments. Everything decorative is
drawn in code (`src/components/Motifs.tsx`, `EyePlate.tsx`, `ProductMotif.tsx`): retinal vessels, an ECG trace,
scanner rings, a helix, a lens barrel. No stock art and no generated images.

- **A hero that looks back.** An illustrated eye inside a measurement dial: a scan line crosses it once, three
  readings (10 diseases, >92% accuracy, under 2 minutes, all from the existing MeiboX copy) are drawn in, then the
  eye follows the visitor's pointer (it drifts on its own until the pointer moves), blinks every few seconds, and
  sends out scan pulses. The pupil widens when you hover BOOK A DEMO. A heartbeat line runs under the hero.
  The caption says it is an illustration. Under *reduce motion* it all stands still.
- **Action dock.** Four ways in, lifted over the bottom edge of the hero; BOOK A DEMO is the loud one.
- **Products on a lit stage.** On the Our Products page only (the Home page no longer repeats them; they are
  reached from the navigation bar): tabs (arrow keys, Home/End, sliding underline, `#meibox` / `#vuopt` /
  `#metabo-x` links), a spec sheet per product, and a stage with a drawn backdrop for each: scanner rings, a helix,
  a lens barrel with rays. MeiboX also has its four-colour imaging strip.
- **Imaging layers.** Pick IR, Visible, Ultrasonic, Fluorescence or All four and the same drawn eye is shown the
  way that type would colour it, next to the four-step "How MeiboX works" timeline. It makes no claim about what
  each type detects; the caption only repeats that MeiboX combines the four, and a note says it is an illustration.
- **Medzak at a glance as an instrument panel.** Four overlapping imaging discs, a half-circle gauge for the 40%
  MTF, a centimetre ruler with 5 to 10 cm lit, and dotted counters for 12 achievements, 13 media features and
  6 supporters. Numbers count up the first time they scroll into view.
- **Who we serve** as three photo cards (the photos share one teal duotone so the stock-looking ones sit with the
  real one); **About** with a framed photo and Mission / Vision / Solution at three sizes; **Recognition by year**
  timeline on the About page, built only from the years already in the achievement titles.
- **Achievements** can be filtered by year; the Home gallery is a mosaic that tiles with no gaps.
- **Inner pages** share the scan-bay header: breadcrumb, title, intro, and scanner rings around an icon for the
  page's subject. Careers and Contact got fuller layouts from copy that was already there.
- **Moving smoothly** (`src/styles/smooth.css`, `components/PageTransitions.tsx`, `components/Link.tsx`):
  - *Page to page*: browsers with View Transitions (Chrome, Edge, Safari 18+) cross-fade the old page into the new
    one; a thin teal bar runs from the click until the new page is on screen, so a slow page never looks stuck.
    Other browsers, and Back/Forward, fade the new page in. Every inner page then opens with the same rise-in as the
    Home hero. Links to the page you are already on scroll to the top; `#section` links scroll there smoothly.
  - *Light to dark*: the new theme spreads outwards from the toggle (colours cross-fade where View Transitions are
    missing).
  - *Content that swaps*: the Achievements year filter eases its cards in, the image viewer fades between pictures and
    keeps the picture while it fades out, dialogs and the search palette arrive with a little travel.
  - Smooth scrolling is the browser's own (`scroll-behavior`), not a scroll-hijacking library, so it follows the
    visitor's system settings; a reserved scroll-bar gutter stops the page shifting sideways when a dialog opens.
  - Everything is off under *reduce motion* (the page then changes instantly) and none of it is needed for the site
    to work.
- **Search**: `Ctrl/Cmd + K` or the magnifier opens a command palette over every page, product and action.
- **Phones**: a bottom bar with Call back, Email, Book demo and Menu; the menu is a full-screen accordion.
- **Updates ticker** has a pause button as well as pausing on hover and focus.
- **Motion** is one idea at a time: the hero sequence on Home, a reveal-on-scroll for section titles and cards
  (content is visible without JavaScript and never stays hidden), and the pointer light on cards. Nothing loops
  that is not hidden or paused under *reduce motion*.

## Nothing removed

Every page, text block, image, link, form field, iframe and ticker item of the static site is still there.
`python scripts/content-check.py` (after `npm run build`) compares `out/` with the static site's content
baseline in `../medzak-website-v2.1/docs/`: 8 pages, 550 text blocks, 114 image references, 260 links,
**0 missing**. It fails when a sentence or image is removed (tested), so a pass means something.

Pages: Home, About Us, Our Products, Achievements & Media, Gallery, Careers, Contact Us, Our Team (not in the
menu, `noindex`), Privacy, Terms, 404, and `why-us` / `our-offerings` which forward to their new pages.

## Forms

The Book-a-Demo, Request-a-Call-Back and Contact forms keep posting to `https://medzak.co/esend.php` with the
same field names. They add: visible labels, inline validation with the first error focused, a hidden honeypot
field, and a sending state. On `medzak.co` itself (same origin as `esend.php`) the request is sent from the
page and a thank-you replaces the form; anywhere else (local preview, another domain) it is a normal form
POST, because a browser cannot read a cross-origin reply. The thank-you wording is the only part that needs
`esend.php`'s real response format to be finished.

## Accessibility and quality checks run on this build

- axe-core (WCAG 2.0/2.1/2.2 A + AA and best-practice rules): every page, light and dark, at 1440 and 390 px:
  no violations.
- Keyboard and screen-reader behaviour tested by script in a real browser: dropdown menus (hover intent, one
  open at a time, arrows, Home/End, Escape returns focus), dialogs (focus moves in, Tab stays inside, Escape
  restores focus, page behind locked), product tabs, carousel, lightbox, search palette, form validation.
- No horizontal scroll on any page at 390, 768, 1024 and 1199 px; no console errors on any page.
- `prefers-reduced-motion` turns off the hero sweep, the ticker movement, the reveal effects, the page cross-fade, the
  theme-switch circle and the photo fade (pages and themes then change instantly; back-to-top jumps).
- Page transitions tested by script in a real browser: a click cross-fades and leaves no state behind on `<html>`;
  Ctrl+click, `#section` links on the same page and links to the page you are on behave natively or scroll smoothly;
  links with a `#section` on another page land on it; Back fades in; the search palette, the phone menu and the quick
  bar still work afterwards; the same flows pass with View Transitions removed and with reduced motion on.

## Layout of the project

```
src/app/            one folder per page (page.tsx), layout.tsx, not-found.tsx
src/components/     SiteHeader, Footer, EyePlate (hero SVG), ProductTabs, Galleries, Lightbox, Modals, forms…
src/data/           all content: nav, products, tiles (achievements, media, gallery), team, site, pages
src/lib/            useEsendForm (validation + sending), meta helpers, image helpers
src/styles/         tokens.css → base.css → header.css → sections.css → components.css → pages.css
public/assets/      images (copied from the static site)
scripts/            gen-images.mjs: writes src/data/images.generated.ts (git-ignored, rebuilt by predev/prebuild)
                    dev.mjs: `npm run dev`, the dev server plus a one-time visit to every page
                    content-check.py: the "nothing removed" check described above
```
